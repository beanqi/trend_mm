# Gate 单市场趋势预测观测与自动训练设计

## 1. 目标和范围

实现一个长期运行的研究服务，用 Gate USDT 永续 BTC-USDT 的盘口和公共成交数据，验证[《趋势预测.md》](趋势预测.md)中模型的实际效果。

第一版范围：

- 只使用 Gate 单市场因子 1～17，暂不计算跨市场因子 18～20。
- 实时计算 10ms、25ms、50ms 三个周期的预测。
- 每秒抽取一个评估样本，并在对应周期到期后补齐真实价格变化。
- 使用 SQLite 保存评估样本、分钟指标和模型版本。
- 自动滚动训练，验证通过后自动切换模型。
- 前端展示实时信号、预测效果、因子贡献和训练历史。

不包含实盘下单、模拟交易 PnL、多个交易对、领先市场和原始逐笔数据长期保存。

## 2. 市场数据接入

不使用 nb-lib，也不引入其他交易所 SDK。项目只使用 reqwest、tokio-tungstenite、serde 和 Decimal 等通用库，直接实现当前需要的 Gate 公开 REST/WebSocket 协议。全部接口都是公开行情接口，不需要 API Key。

数据来源以 [Gate Futures WebSocket](https://www.gate.com/docs/developers/futures/ws/en/) 和 [Gate Futures REST](https://www.gate.com/docs/developers/apiv4/en/futures/) 官方文档为准：

- 启动时查询 BTC_USDT 合约信息，从 order_price_round 读取 tick_size；读取失败时保持 warming，不使用硬编码精度生成预测。
- 深度订阅使用 futures.obu 的 ob.BTC_USDT.50 流。首包完整快照直接建立本地盘口，后续按 U/u 序号应用增量；重复收到完整快照时整体替换。
- 本地维护 50 档盘口，模型只读取最优的前 10 档。序号不连续时立即丢弃当前盘口，取消并重新订阅以取得新快照。
- 公共成交订阅 futures.trades，使用成交 ID 去重，根据 size 正负判断主动买卖方向，并忽略不反映正常盘口撮合的 internal trade。
- WebSocket 读循环负责心跳、超时检测和指数退避重连；重连后重新获取合约信息、盘口快照和短窗口状态。

官方深度 V2 的 50 档流按 20ms 推送，因此 10ms 标签仍可评估，但盘口订单流因子只能基于 20ms 批次，无法还原真正的 10ms 逐事件盘口变化。页面和模型版本信息必须显示这个数据粒度限制。

## 3. 最小架构

采用单个 Rust 进程，内部按职责拆成普通模块：

    Gate REST/WS
            │
            ▼
       gate_market
            │
            ▼
       signal_engine ──────► live_state ──────► Web/SSE
            │
            ▼
        evaluator ─────────► SQLite writer ───► 历史查询
                                  │
                                  ▼
                               trainer
                                  │
                                  ▼
                            active_model 原子切换

各模块职责：

- gate_market：直接连接 Gate 公共 REST/WebSocket，维护连续的本地盘口并把深度、成交事件发送给计算任务，不在 WebSocket 读循环里计算或写库。
- signal_engine：唯一持有当前盘口、10ms/50ms 事件窗口、EWMA 归一化状态和最新因子，避免共享可变状态。
- evaluator：每秒创建一次预测样本，补齐未来 10ms、25ms、50ms 的真实标签。
- trainer：按计划读取已完成标签的样本，训练候选模型并完成验证。
- storage：由单独写入任务批量操作 SQLite；实时计算路径不直接访问数据库。
- web：提供只读 API、SSE 实时推送和一个静态前端页面。

第一版不引入通用行情接口、插件系统或多模型 Trait。

## 4. 实时计算与评估

### 4.1 因子输入

盘口更新使用本地盘口应用增量前后的前十档差值计算新增量和减少量，公共成交提供主动买卖量。对同一价格、方向及相邻盘口更新时间范围内的成交量，优先从盘口减少量中匹配；剩余减少量视为撤单。这是市场深度流无法直接区分成交与撤单时的明确近似规则。

所有滚动窗口和预测周期使用本机单调时钟，交易所时间只用于排查数据质量。成交按成交 ID 去重；盘口序号不连续时由 gate_market 重新订阅并取得完整快照，同时清空短窗口。

只计算因子 1～17。冷启动权重从原表中删除因子 18～20 后，分别按以下总和重新归一化：

- 10ms 权重除以 75%。
- 25ms 权重除以 65%。
- 50ms 权重除以 55%。

因子继续使用 120 秒 EWMA 均值和方差归一化。启动、重连或长时间数据中断后进入 warming 状态，重新积累足够状态前不写入有效样本。

### 4.2 预测与标签

盘口或成交事件到达时更新因子和最新预测；发往前端的实时状态最多每 100ms 更新一次。

评估采样固定为每 1 秒一次。每个样本包含：

- 采样时间、当前 mid 和 tick_size。
- 17 个归一化因子。
- 使用的模型版本。
- 三个周期的预测 tick 数。
- 三个周期的实际变化 tick 数。
- 数据质量状态。

evaluator 保存最近的 mid 时间序列。标签到期后，取目标时刻之前最后一个有效 mid 计算实际变化，避免任务调度稍晚导致标签偷看未来。50ms 标签完成后整行写入 SQLite；数据缺失或过期则将该周期标为无效。

### 4.3 评估指标

按 10ms、25ms、50ms 分别计算：

- 有效样本覆盖率。
- Pearson IC，即预测值和实际值的相关性。
- MAE 和 RMSE，单位为 tick。
- 方向准确率；只统计实际变化非零且预测绝对值达到配置阈值的样本。
- 预测分桶后的平均实际变化，用于观察预测是否具有单调性和校准偏差。

这些指标只说明预测质量，不解释为可交易收益。

## 5. 自动训练与模型切换

### 5.1 训练计划

- 首次积累满 24 小时有效数据后开始训练。
- 此后每 6 小时训练一次。
- 每次最多读取最近 7 天数据；不足 7 天时使用已有的全部数据。
- 数据严格按时间排序，前 80% 用于训练，后 20% 用于验证，不随机打乱。
- 三个 horizon 分别拟合，但作为同一个模型版本一起发布。

冷启动模型使用重新归一化后的初始权重，截距为 0、尺度为 1，并在页面明确显示为 provisional。

### 5.2 训练形式

为简化原公式，把 c_h 与 w_h 合并为非负系数 beta_h：

    y_hat_h = a_h + beta_h · x

对每个 horizon 做带先验的非负 Ridge 回归：

    min Σ(y - a - beta · x)² + lambda ||beta - beta_prior||²
    subject to beta >= 0

beta_prior 首次来自冷启动参数，以后来自当前生效模型。训练完成后可用 c = Σ beta、w = beta / c 还原页面需要展示的尺度和权重。这样保留“所有因子正值代表上涨”和“权重非负”的约束，同时避免联合优化 c 与 w 的额外复杂度。

### 5.3 验证和切换

候选模型与当前模型必须在同一段验证集上重新计算指标。默认启用条件：

- 三个 horizon 的平均 RMSE 至少改善 1%。
- 任一 horizon 的 IC 下降不超过 0.01。
- 样本量、覆盖率和所有参数均通过有效性检查。

阈值放入配置。未通过的候选模型记录为 rejected，当前模型保持不变；通过后记录为 active，并通过单一模型管理器原子切换。训练在后台阻塞任务中运行，不暂停行情和预测。进程重启时加载最后一个 active 模型。

## 6. 持久化

SQLite 开启 WAL，由单写入任务负责事务。只需要三张核心表：

### evaluation_samples

保存每秒评估明细：时间、mid、归一化因子 JSON、模型版本、三个预测、三个标签和质量状态。增加 feature_version，因子实现变化后禁止混用旧样本训练。

### model_versions

保存版本状态、训练和验证时间范围、每个 horizon 的截距与系数、训练参数、验证指标、创建和启用时间。

### metric_minutes

按分钟、模型版本和 horizon 保存覆盖率、IC 所需统计量、MAE、RMSE、方向命中数及样本数。

评估明细保留 30 天，分钟聚合永久保留。清理任务每天运行一次，确认分钟聚合已生成后再删除过期明细。自动训练只读取最近 7 天明细。

## 7. 前端与接口

前端使用由 Rust 服务直接托管的静态 HTML、CSS、JavaScript，图表资源随程序部署，不增加独立 Node 服务。

单页展示：

- 连接状态、数据年龄、运行状态、当前模型版本和下次训练时间。
- 最近 5 分钟的 mid、预测 tick 与实际 tick 曲线，可切换 horizon。
- 1 小时、24 小时、7 天的覆盖率、IC、MAE、RMSE 和方向准确率。
- 当前 17 个因子值、三个 horizon 的权重和因子贡献。
- 模型版本、训练区间、验证指标及 active/rejected 状态。

最小接口：

- GET /api/status：运行状态和当前模型。
- GET /api/stream：通过 SSE 推送最新预测和因子，约 100ms 一次。
- GET /api/samples：按时间范围和 horizon 查询历史曲线，服务端限制点数并降采样。
- GET /api/metrics：查询聚合指标。
- GET /api/models：查询训练历史。

## 8. 运行状态与失败处理

服务运行阶段分为 warming、running、degraded，训练是否正在执行作为独立状态展示，避免后台训练时误报服务已停止运行。

- 行情断连、盘口序号异常或十档不完整：停止生成有效样本，重新订阅取得完整快照后重建短窗口。
- SQLite 写入失败：实时预测可以继续，但标记 degraded、暂停训练并在页面告警。
- 训练失败或候选模型不合格：记录错误并继续使用当前模型。
- 进程重启：恢复 active 模型和数据库，行情窗口与 EWMA 从头预热。

主要配置只包括 symbol、数据库路径、采样周期、保存天数、训练周期、训练窗口、Ridge lambda 和模型启用阈值。tick_size 每次启动从 Gate 合约信息读取。第一版 symbol 固定为 BTC-USDT，不设计多交易对配置结构。
